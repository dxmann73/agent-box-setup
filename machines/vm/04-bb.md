# 04 – BB

[BB](https://getbb.app/) is the agent interface. The personal host's AppImage server is the shared
control plane. Enroll the VM into it as an execution machine so remote clients can select the host
or VM. The VM's headless server may remain temporarily as an independent fallback while that shared
path is tested.

Sources checked September 10, 2026:

- [Package guide](https://github.com/get-bb/bb/blob/main/packages/bb-app/README.md)
- [Platform support](https://github.com/get-bb/bb/blob/main/docs/platform-support.md)

## 1. Prerequisites

The guest baseline installs Node 24, a user-owned npm prefix, and the four provider CLIs. BB
supports Node 22.19+, 24, and 26 release lines. Provider authentication is not a prerequisite for BB
installation; enable it later using [credentials](05-credentials.md). Host login credentials never
transfer to the VM.

```bash
node --version
npm config get prefix
command -v claude codex agent pi
```

## 2. Install and persist

Follow [the shared BB runtime guide](../common/05-bb.md). It installs a dedicated npm runtime and a
loopback-only systemd user service on this machine.

## 3. Standalone fallback access

For the initial local setup, tunnel the guest's loopback listener over SSH:

```bash
ssh -N -L 38887:127.0.0.1:38886 VM_NAME
```

Open `http://127.0.0.1:38887` on the host for VM work; the host's own instance remains at
port 38886. Closing this tunnel disconnects the browser but leaves the VM service running. Reconnect
to resume viewing it.

For private access from other devices, this box may publish the loopback server over Tailscale. See
`infra/tailscale/serve.md`. Do not expose the unauthenticated raw BB API to the LAN or public
Internet. No wildcard listener or router port forwarding is needed.

The guest origin shows only the standalone guest server. Do not use it when the client needs both
execution machines.

## 4. Enroll into the shared host server

First ensure the host AppImage server is the client entry point. From the host server, create a
manual machine enrollment and run the one-time private command inside the VM:

```bash
bb machine create --provider manual
```

The installer creates isolated state under `~/.bb-machines/` and a separate systemd user service. It
must not reuse or overwrite the standalone server's `~/.bb/` state. Rename the enrolled machine to
`VM_NAME`, then verify from the host:

```bash
bb machine list
bb provider list --machine VM_NAME
```

Do not commit or log the enrollment command.

## 5. Remote clients

Desktop clients and the Android browser-installed web app connect to the shared host origin, not the
standalone guest origin. Follow [the shared BB guide](../common/05-bb.md) for Android setup.

## 6. Updates and state

The host desktop and VM server are independent installations. Update the VM runtime deliberately
after its agents and terminals are idle:

```bash
systemctl --user stop bb.service
npm install -g --prefix ~/.local/share/bb-runtime \
  --allow-scripts=better-sqlite3,node-pty,@parcel/watcher bb-app@<chosen-version>
systemctl --user start bb.service
systemctl --user status bb.service
```

Record the old version and preserve `~/.bb/` before an upgrade when recovery is required.
Configuration may live in `~/.bb/config.json`; provider credentials and state stay private and are
not committed. A service restart or VM reboot is not a promise that running processes resume; client
disconnect persistence is a separate behavior to test.

## 7. Checklist

Use supervised provider permissions on the personal host. Unrestricted agent execution belongs
inside the VM boundary. Projects live in `~/projects` on their execution machine. Opening a VM URL
does not enroll the browser's host machine.

- [ ] BB service starts and serves its browser UI
- [ ] provider CLIs are visible inside the VM; authentication is a later explicit phase
- [ ] a test thread reports the VM hostname and edits only its VM project
- [ ] disconnect and reconnect the client while a terminal job runs; job survives
- [ ] two concurrent agent sessions remain visible after reconnecting
- [ ] service starts after VM reboot with lingering enabled
- [ ] raw port 38886 is loopback-only; remote access uses SSH or private HTTPS
- [ ] VM is enrolled and connected as an execution machine of the host server
- [ ] Android may open the host origin recorded in infra
- [ ] shared clients can select either machine; unrestricted tasks use the VM
