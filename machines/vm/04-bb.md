# 04 – BB

[BB](https://getbb.app/) is the agent interface. The personal host is the shared control plane.
Enroll the VM as an execution machine so remote clients can select the host or VM from the same BB
origin.

Sources checked September 10, 2026:

- [Platform support](https://github.com/get-bb/bb/blob/main/docs/platform-support.md)
- [Multiple devices](https://github.com/get-bb/bb/blob/main/docs/multiple-devices.md)

## 1. Prerequisites

The guest baseline installs Node 24 and the four provider CLIs. Provider authentication is not a
prerequisite for BB enrollment; enable it later using [credentials](05-credentials.md). Host login
credentials never transfer to the VM.

```bash
node --version
npm config get prefix
command -v claude codex agent pi
```

BB must already be running on the host. Follow [the shared BB guide](../common/05-bb.md) first.

## 2. Enroll into the shared host server

From the host server, create a manual machine enrollment and run the one-time private command inside
the VM:

```bash
bb machine create --provider manual
```

The installer creates isolated state under `~/.bb-machines/` and a separate systemd user service for
the enrolled host daemon. Rename the enrolled machine to `VM_NAME`, then verify from the host:

```bash
bb machine list
bb provider list --machine VM_NAME
```

Do not commit or log the enrollment command.

## 4. Remote clients

Desktop clients and the Android browser-installed web app connect to the shared host origin, not a
guest origin. Follow [the shared BB guide](../common/05-bb.md) for Android setup.

## 5. Updates and state

VM enrollment creates a managed host-daemon service under `~/.bb-machines/`. BB manages that
service; the repo's weekly tooling update does not touch it.

Configuration, provider credentials, and project state stay private to the machine where they live.
A VM reboot should restart the enrolled host-daemon service, but running agent process survival is a
separate behavior to test.

## 6. Checklist

Host and VM agents use YOLO settings. Host sudo stays password-protected. Projects live in
`~/projects` on their execution machine.

- [ ] `~/.bb-machines/` exists after enrollment
- [ ] VM is enrolled and connected as an execution machine of the host server
- [ ] provider CLIs are visible inside the VM; authentication is a later explicit phase
- [ ] a test thread reports the VM hostname and edits only its VM project
- [ ] disconnect and reconnect the client while a terminal job runs; job survives
- [ ] two concurrent agent sessions remain visible after reconnecting
- [ ] shared clients can select either machine; project agent work uses the VM
- [ ] Android may open the host origin recorded in infra
