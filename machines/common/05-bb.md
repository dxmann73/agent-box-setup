# 05 – BB desktop app and shared access

Use the official Linux desktop AppImage on the personal host. It bundles the BB UI, server and host
daemon, starts them when the app opens, and stops the processes it owns when the app quits. The host
server is the shared control plane; the VM is enrolled into it as an execution machine.

## Host: desktop AppImage

Download the current `x86_64.AppImage` from the
[official BB desktop release](https://github.com/get-bb/bb/releases/latest), make it executable and
store it in a user-writable application directory. A writable directory allows BB's built-in updater
to replace the AppImage safely.

```bash
mkdir -p ~/Applications
mv ~/Downloads/bb-*-x86_64.AppImage ~/Applications/bb.AppImage
chmod +x ~/Applications/bb.AppImage
~/Applications/bb.AppImage
```

The desktop app uses `~/.bb/` for BB state.

Kubuntu does not integrate an AppImage into the application menu on its own; that only happens with
`appimaged` installed. Create the menu entry explicitly. Without it, the only `bb` that KRunner
finds is the CLI at `~/.local/bin/bb`, which prints help and exits 1 — it looks like the app refuses
to start.

```bash
ln -s ~/projects/agent-box-setup/user-home/applications/bb.desktop \
      ~/.local/share/applications/bb.desktop
```

That entry sets `Icon=bb`, and nothing else on the system ships that icon. Extract it from the
AppImage:

```bash
mkdir -p ~/.local/share/icons/hicolor/1024x1024/apps
tmp=$(mktemp -d)
(cd "$tmp" && ~/Applications/bb.AppImage \
    --appimage-extract usr/share/icons/hicolor/1024x1024/apps/bb.png)
cp "$tmp/squashfs-root/usr/share/icons/hicolor/1024x1024/apps/bb.png" \
   ~/.local/share/icons/hicolor/1024x1024/apps/bb.png
rm -rf "$tmp"
update-desktop-database ~/.local/share/applications
gtk-update-icon-cache -f -t ~/.local/share/icons/hicolor
kbuildsycoca6
```

The entry also carries `StartupWMClass=bb`, copied from the entry bundled in the AppImage. On
Wayland that is what maps the running window back to the launcher.

The [`bb-server` module](../../modules/05-dev/bb-server/recipe.md) does all of this, plus the
autostart entry and the FUSE package, in one idempotent `apply.sh`.

To start BB automatically at KDE login, create a desktop autostart entry:

```bash
mkdir -p ~/.config/autostart
cat > ~/.config/autostart/bb.desktop <<'EOF'
[Desktop Entry]
Type=Application
Name=BB
Comment=Agent development environment
Exec=/home/you/Applications/bb.AppImage
Terminal=false
X-GNOME-Autostart-enabled=true
EOF
sed -i "s|/home/you|$HOME|" ~/.config/autostart/bb.desktop
```

KDE runs that entry after login. Disable it by removing `~/.config/autostart/bb.desktop` or through
System Settings → Autostart.

AppImage execution normally requires FUSE. On Ubuntu/Kubuntu, install the compatibility package if
the app reports a FUSE error:

```bash
sudo apt install -y libfuse2t64
```

As a temporary fallback when FUSE is unavailable:

```bash
~/Applications/bb.AppImage --appimage-extract-and-run
```

Do not also enable this repository's `bb.service` on the host. A leftover service can occupy BB's
default port or cause the desktop app to attach to a separately managed runtime. Disable the old
browser-runtime setup after closing any active BB work:

```bash
systemctl --user disable --now bb.service
```

## VM enrollment

Enroll the agent VM from the host server using [the VM BB guide](../vm/04-bb.md). Enrollment creates
a VM-side host-daemon service under `~/.bb-machines/` so the host server can run work on the VM.

## Baseline server preferences

These commands are server-backed state in the host `~/.bb/`, not project state. Re-run them after
creating a fresh host BB data directory. The host AppImage must already be running.

Pin the sidebar to project organization on each BB server after first launch:

```bash
bb settings ui set sidebar.organizationMode project
```

Enable the built-in Provider usage plugin. It is off by default; without it the usage card is
missing from the sidebar footer. Run it on the host server after the AppImage first launch.

```bash
bb plugin enable provider-usage
```

Once enabled, usage appears in the sidebar footer and in the plugin settings page. Restore a hidden
footer action from Settings → Appearance → Sidebar footer.

## Shared access and Android

Remote clients may reach the host BB origin over Tailscale. This box's host URL lives in
`~/projects/infra/tailscale/`. Do not hardcode it here.

The host AppImage must be running and the laptop must be awake.

On an Android phone:

1. Open the shared host origin from infra in Chrome.
1. Use Chrome's menu and select **Install app** or **Add to Home screen**.
1. Launch BB from the new home-screen icon.
1. Confirm that the host and `VM_NAME` are available as execution machines.

The installed web app is the Android client; it does not make the endpoint public or copy BB state
onto the phone.
